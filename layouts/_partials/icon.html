{{- /* icon.html — inline SVG icon, read from Iconify data. WHY IT IS INLINE. Icons are inlined rather than loaded as a font, an external sprite or a JS icon library: they inherit `currentColor` (so the dark theme needs no extra work), they cannot flash, they add no request, and — unlike an external SVG sprite referenced with — no cross-document styling rules apply. WHERE THE PATHS COME FROM. Hugo has no icon system: `hugo gen` offers only chromastyles, doc and man. So the paths live in IconifyJSON collections — the format the Iconify project publishes for 200 000+ icons — under `assets/icons/`, and are read with `resources.Get` + `transform.Unmarshal`: assets/icons/lucide.json vendored subset, upstream spelling kept in `icons`, template spelling in `aliases` assets/icons/local.json marks that belong to no set (the brand mark) The data is COMMITTED and the lookup is pure Hugo, so the build needs no npm package, no script and no network. Adding an icon is an edit to one JSON file; the warning below hands you the exact URL to copy the body from. Dropping one of Iconify's own `icons.json` archives in under the same name also works — same shape, same lookup — which is how you would get a whole set at once.
